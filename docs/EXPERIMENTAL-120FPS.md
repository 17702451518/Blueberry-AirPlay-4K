# 实验性 120 帧与任务栏分组

此版本增加 2K120、4K120 HEVC 低延迟请求，原有 4K60 默认配置保持不变。没有 iPhone Pro 实机验证，不应宣传为已经实现或保证 120 FPS 投屏。

## 为什么只能标为实验性？

iPhone 屏幕的 120Hz 刷新率不等于无线投屏视频的实际帧率。UxPlay 1.73.6 的 `-s 宽x高@120` 与 `-fps 120` 可以公布刷新率和最大帧率请求，但 iOS 可以发送更低帧率。

- [对应版本源码中的参数处理](https://github.com/FDH2/UxPlay/blob/v1.73.6/uxplay.cpp)
- [上游帧率选项说明](https://github.com/FDH2/UxPlay/blob/v1.73.6/README.md)

## 高刷新率设备验证步骤

1. 先用原有 4K60 确认能正常投屏。
2. 展开“实验性 120 帧”，先选 2K120，阅读提示后启动；手机重新连接屏幕镜像。
3. 连续滚动或播放高帧率内容，检查画面、延迟、温度和音画同步。静止画面不能用于判断最高帧率。
4. 2K120 稳定后再试 4K120。黑屏或卡顿时改回 4K60 并重连。
5. 反馈手机/iOS、电脑显卡、显示器刷新率、所选模式。120Hz 显示器设置与模式名称都不是实际接收帧率证据；只有可靠的接收端帧率测量才能确认 120 FPS。本版尚未提供实时测量面板。

## 任务栏

控制台运行期间，为同目录接收程序的可见窗口设置相同的 Windows AppUserModelID，使其与控制台归入同一个任务栏按钮。窗口仍独立，可通过缩略图切换；不改变窗口父子关系，不改动解码或渲染。

依赖 Windows 的任务栏合并设置；“从不合并”时仍可有多个按钮。本项目不更改全局系统设置。仅独立启动接收核心、不运行控制台时不会应用此分组。新窗口出现后约一秒内分组。
