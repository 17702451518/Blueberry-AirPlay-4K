# 性能与画质说明

## 分辨率、帧率和码率

内置模式向发送端声明接收能力，并设置接收端输出上限。iOS 会根据设备、内容、网络和运行状态动态决定实际编码参数，所以“选择 4K60”不等于每一帧都以原生 3840×2160、60 FPS 和固定高码率发送。

项目不提供固定码率滑块：UxPlay 接收端不能可靠地用这一数值强制 iPhone 编码器，加入该控件会制造错误预期。

## 低延迟模式

“4K60 低延迟互动”增加 `-vsync no`，让视频帧到达后尽快显示，适合界面操作、演示和游戏。标准模式保留时间戳同步，更适合视频和对音画同步敏感的内容。

## D3D11 路径

完整包包含 GStreamer 的 D3D11 解码/渲染插件。控制台固定写入 `renderer_mode=d3d11`，用于避开部分显卡上 D3D12 初始化、冻结或黑屏问题；这不保证每台机器都使用同一种硬件解码器，最终选择仍取决于驱动和 GStreamer 插件协商。

## 首帧延迟

接收器可以在连接前预启动，但 AirPlay 会话协商、iPhone 编码器启动、解码器创建和第一张纹理上传仍发生在每次新连接中。低延迟模式主要减少持续播放阶段的排队，不会让首帧初始化归零。

## 色彩

当前模式不强制注入 BT.709、sRGB、全范围或 HDR 元数据。白色或整体色调偏差可能来自：

- iPhone 夜览、原彩或 HDR；
- Windows HDR、ICC 配置或显示器模式；
- 显卡驱动的动态范围、色彩增强与视频后处理；
- 流中的色域/范围标记与接收端转换；
- 有损压缩和色度子采样。

排查时应一次只改变一个环节，并用相同显示器上的本地原图作对照。

## 网络建议

电脑有线连接、移动设备使用稳定的 5 GHz/6 GHz Wi-Fi 通常比盲目提高请求参数更有效。避免访客网络、客户端隔离、拥塞信道和不必要的 VPN；先用 1080P60 验证链路，再逐级提高。
